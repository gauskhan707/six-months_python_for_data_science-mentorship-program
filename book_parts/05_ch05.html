Core data

Operators

▾

What/why. Operators are the verbs of code: compact symbols that do things to values (+ - * / // % ** == != < and or not in is & |). Python groups them into seven families. The professional skill is not memorizing symbols — it is mastering precedence (which operator grabs its operands first), short-circuit evaluation (which work gets skipped, and why that's a feature), chaining (Python's elegant a < x < b), and the four classic traps: == vs is, mutating +=, floor-division with negatives, and or-defaults swallowing valid zeros.

Why so many? Each family answers a different question kind: arithmetic computes, comparison judges, logical combines judgments, assignment stores, identity identifies, membership searches, bitwise packs flags into integers. Confusing families (& for and, is for ==) is a rite of passage — this chapter vaccinates you.

Analogy. Operators are sentence verbs and conjunctions: arithmetic verbs transform nouns (total + tax), comparisons ask yes/no questions (age >= 18?), logical operators build compound questions ("adult and member?"), and assignment files the answer (status = …). Precedence is punctuation — it decides which words group together before you read the sentence.

5.2 Arithmetic, deeply: the division trio, modulo, and power

What — three divisions, three meanings: / is true division (always float: 7/2 → 3.5, even 4/2 → 2.0); // is floor division (quotient rounded down toward −∞: 7//2 → 3); % is modulo (remainder with the divisor's sign). They obey one inviolable law: a == (a // b) * b + (a % b) — always, including negatives.

division trio + the negative surprise, explained 
print(7 / 2)     # 3.5 — true division, ALWAYS float
print(7 // 2)    # 3 — floor(3.5) = 3
print(7 % 2)     # 1 — remainder; 7 == 3*2 + 1 ✓
print(divmod(7, 2))   # (3, 1) — quotient AND remainder, one call
print(-7 // 2)   # -4 — NOT -3! floor(-3.5) = -4 (toward -infinity)
print(-7 % 2)    # 1 — sign follows the DIVISOR: -7 == (-4)*2 + 1 ✓
print(7 % -2)    # -1 — divisor negative → remainder negative
print(2 ** 10, 2 ** 0.5, 9 ** 0.5)  # 1024 1.414... 3.0 — ** does roots too
3.5 3 1 (3, 1) -4 1 -1 1024 1.4142135623730951 3.0

Step-by-step (-7 // 2 == -4). True quotient: −3.5. // floors toward negative infinity: the integers around −3.5 are −4 and −3; the lower is −4. Then % is defined by the law: -7 == (-4)*2 + r → r = 1. C/Java truncate toward zero instead (-7/2 → -3) — Python's choice makes modulo mathematically clean for wraparound (clock arithmetic, circular buffers, array rotation: items[i % len(items)] works even for negative i — try that in C!).

Multiple examples — modulo's greatest hits:

modulo patterns you'll reuse forever 
# Even/odd, every-Nth, wraparound, last digit
print([n % 2 == 0 for n in range(5)])   # [True, False, True, False, True]
days = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
print(days[10 % 7])    # Thu — wraparound indexing (10 % 7 = 3 → days[3])
print(12345 % 10)      # 5 — last digit
print(divmod(125, 60)) # (2, 5) — 125 min = 2h 05min (time math!)
# Power quirks: right-associativity + unary minus
print(2 ** 3 ** 2)     # 512 — parsed as 2**(3**2), NOT (2**3)**2=64
print(-3 ** 2)         # -9 — ** binds TIGHTER than unary minus: -(3**2)
print((-3) ** 2)       # 9 — parens force intent
[True, False, True, False, True] Thu 5 (2, 5) 512 -9 9
⚠️ Common mistakes-3 ** 2 → -9 (bind order!); 2 ** 3 ** 2 → 512 (right-assoc); 10 % 3.5 works on floats (→ 3.0) but inherits float dust; % by zero → ZeroDivisionError (same as /); huge ** (e.g. 10 ** 10**8) hangs allocating gigadigits — use modular pow(a, b, mod) for crypto-scale work.

5.3 Precedence: the silent decider (with proof-by-example)

What. Precedence ranks operators: higher-precedence operators grab their operands first, as if parenthesized. Associativity breaks ties: left-assoc (a - b - c = (a-b)-c) vs right-assoc (**). Python's order (highest → lowest), with only the rows that actually bite:

precedence traps, each annotated 
print(2 + 3 * 4)              # 14 — * first (school rules survive)
print(10 - 2 ** 3)            # 2 — ** before -: 10-8
print(not 1 == 2)             # True — parsed as not (1==2), NOT (not 1)==2
print(False or True and False)      # False — and binds tighter: False or (True and False)
print(True or True and False)       # True — same grouping: True or (…)
print((False or True) and False)    # False — parens OVERRIDE (always parenthesize!)
14 2 True False True False

Best practice (unambiguous). Memorize only: arithmetic before comparison before not before and before or — and parenthesize everything else. Parens cost nothing, prevent all precedence bugs, and document intent. Code review rule: if a reader must recall the table, the code needs parens.

5.4 Comparison chaining: Python's elegant superpower

What. Consecutive comparisons chain: a < b < c means (a < b) and (b < c) — with b evaluated only once. Chains can mix operators (1 <= x < 10 != y) and stretch arbitrarily long. Each link must hold for the whole to be True; evaluation short-circuits (stops at the first False link).

chaining: beauty + one surprise 
age = 25
print(18 <= age < 65)        # True — "working age" in one breath
print(18 <= age < 20)        # False — second link fails
# Single evaluation proof: b computed ONCE
calls = []
def tracked(v):
    calls.append(v)
    return v
print(0 < tracked(5) < 10, "| calls:", calls)  # True | calls: [5] — once!
# ⚠️ Surprise: == chains too!
a, b, c = 1, 1, 2
print(a == b == c)   # False — means (a==b) and (b==c): True and False
print((a == b) == c) # False too — but means (True)==2 → False (different!)
True False True | calls: [5] False False

Why single-evaluation matters. low() < expensive(x) < high() calls expensive once — both faster and correct if the function has side effects or returns different values per call (timestamps, random draws, consumed iterators). The naive expansion e > low() and e < high() with e = expensive(x) matches it — but the chain is shorter and can't drift out of sync.

⚠️ Common mistake: chained == isn't "all equal to the first"a == b == c checks adjacent pairs — fine for equality (transitive), but a < b == c means (a<b) and (b==c), which surprises readers expecting grouping. Mixed chains are legal but often unclear — parenthesize or split when mixing operators.

5.5 Logical operators: short-circuiting operand-returners

What. and/or evaluate operands left to right and stop at the first value that decides the outcome (short-circuiting), returning that operand itself — not necessarily a boolean. Rules: or returns the first truthy operand (or the last operand if none); and returns the first falsy operand (or the last operand if none). not x always returns a real bool (True iff x is falsy).

Why this design. Two wins: (1) efficiency + safety — skipped operands never execute, so guards like if items and items[0] == x: can't IndexError (if items is empty/falsy, items[0] never runs); (2) idioms — name or "guest" (defaults), cond and value (conditional values) fall out naturally.

short-circuit: proofs + idioms + the trap 
# Proof 1: skipped work never runs (no crash!)
print(False and 1/0)   # False — 1/0 NEVER evaluated
print(True or 1/0)     # True — 1/0 NEVER evaluated
# Proof 2: operands returned, not bools
print("" or "guest")       # 'guest' — first truthy
print("ali" or "guest")    # 'ali' — first truthy (second skipped)
print("a" and "b" and "")  # '' — first falsy
print("a" and "b" and "c") # 'c' — all truthy → last
print(not 0, not "hi")     # True False — not ALWAYS makes bool
# The idiom...
print(0 or 5)              # 5
# ...and its TRAP: 0/"" /[] may be VALID values!
qty = 0
print(qty or 10)                       # 10 — WRONG if 0 means "none ordered"
print(qty if qty is not None else 10)  # 0 — correct: only None triggers default
False True guest ali c True False 5 10 0

Step-by-step ("a" and "b" and ""). and scans: "a" truthy → continue; "b" truthy → continue; "" falsy → stop, return "". Nothing after it would run. This left-to-right-with-early-exit walk is also exactly how chained comparisons (§5.4) and any()/all() (Chapter 20) behave — one mental model, three constructs.

⚠️ The eternal beginner bugif answer == "y" or "yes": is always True — it parses as (answer == "y") or ("yes"), and the non-empty string "yes" is truthy. Correct: if answer in ("y", "yes"): — membership (§5.6) is the multi-option test.

5.6 Identity, membership, and bitwise (each with its real job)

Identity (is). Same-object test (§3.2). Correct uses: x is None, flag is True (rare — if flag: suffices), sentinel checks. Never for values. is not is its negation (if row is not None:).

Membership (in). Searches containers — with wildly different costs: list/tuple/str scan element-by-element — O(n); set/dict hash directly — O(1) average. For dict, in tests keys only ("a" in {"a": 1} → True; 1 in {"a": 1} → False). For strings, tests substrings ("cat" in "concatenate" → True).

membership semantics + the set speedup 
print("a" in "cat", "z" not in "cat")   # True True — substring test
print("k" in {"k": 1}, 1 in {"k": 1})    # True False — KEYS only!
print(2 in [1, 2, 3], 9 in {1, 2, 3})    # True False
# The 1000× pattern (Chapter 24 proves it): hash once, lookup O(1)
import time
big_list = list(range(200_000))
big_set = set(big_list)
t0 = time.perf_counter(); _ = 199_999 in big_list; t_list = time.perf_counter() - t0
t0 = time.perf_counter(); _ = 199_999 in big_set; t_set = time.perf_counter() - t0
print(f"list: {t_list*1000:.2f}ms  set: {t_set*1000:.4f}ms")
True True True False True False list: 2.10ms set: 0.0008ms

Bitwise (& | ^ ~ << >>). Operate on the binary digits of ints. Real jobs: (1) flag packing — many booleans in one int (READ=4, WRITE=2, EXEC=1; perm = READ | WRITE; test with perm & WRITE); (2) masks (value & 0xFF keeps the low byte); (3) shifts (x << 3 = ×8, x >> 1 = ÷2 floored). In Pandas/NumPy, &/| combine boolean masks elementwise — and since bitwise binds tighter than comparisons (§5.3), you must parenthesize: (df.a > 0) & (df.b < 5). Forgetting the parens is the most common Pandas TypeError/ValueError in existence.

bitwise, bit by bit 
a, b = 0b1100, 0b1010   # 12, 10
print(bin(a & b))  # 0b1000 (8) — 1 where BOTH have 1
print(bin(a | b))  # 0b1110 (14) — 1 where EITHER has 1
print(bin(a ^ b))  # 0b110 (6) — 1 where they DIFFER
print(bin(a << 2)) # 0b110000 (48) — shift left = ×4
# Flags in action:
READ, WRITE, EXEC = 4, 2, 1
perm = READ | WRITE            # 6 — grant read+write
print(perm, bool(perm & EXEC))  # 6 False — exec bit not set
perm |= EXEC                   # grant exec → 7
perm &= ~WRITE                 # revoke write → 5
print(perm)
0b1000 0b1110 0b110 0b110000 6 False 5

5.7 Assignment family + walrus, deeply

Augmented assignment (+= -= *= …) rebinds x = x OP value — except mutables implement in-place versions: list += … extends in place (aliases see it), while lst = lst + … builds new (aliases don't) — §3.7's proof. Walrus (:=, 3.8+) assigns inside an expression and evaluates to the assigned value — for "compute once, test, and keep":

walrus: compute-test-keep 
data = [1, 2, 3, 4]
if (n := len(data)) > 3:     # assign n AND test it — one pass
    print("many:", n)         # n survives after the if! → many: 4
# Without walrus: len(data) twice, or a temp line before the if.
# Loop idiom: read until sentinel
lines = iter(["a", "b", "STOP", "c"])
while (line := next(lines)) != "STOP":
    print("got:", line)       # got: a / got: b — then stops, "c" never read
many: 4 got: a got: b
⚠️ Walrus restraintThe walrus binds in the surrounding scope (even inside comprehensions/if-conditions — it leaks by design). Use it for exactly this pattern (use-twice value in a test); nested walruses and walrus-in-comprehension heroics are write-only code. When in doubt, write the extra line.

5.8 Interview questions

Q1: Explain // with negatives: why is -7 // 2 == -4 and -7 % 2 == 1?
// floors toward −∞: −7/2 = −3.5 → −4. % is defined by the invariant a == (a//b)*b + (a%b): −7 == (−4)(2) + 1. The divisor's sign determines the remainder's sign. Benefit: wraparound indexing and clock arithmetic work uniformly for negatives.
Q2: What does `or` return, exactly? When is `x or default` wrong, and what's the fix?
or returns the first truthy operand, else the last — an operand, not a bool. x or default wrongly replaces valid-but-falsy 0/"" /[]. Fix when only None means missing: x if x is not None else default.
Q3: `a += b` vs `a = a + b` — when do they differ?
For immutables they're equivalent (both rebind to a new object). For mutables with in-place methods (list __iadd__), += mutates in place — aliases observe it; = … + … builds new and rebinds only that name. Prove with id() + an alias witness.
Q4: Why do Pandas filters need parens: `(df.a > 0) & (df.b < 5)`?
& (bitwise) binds tighter than comparisons, so df.a > 0 & df.b < 5 parses as df.a > (0 & df.b) < 5 — garbage. Parens force the comparisons first; & then combines the boolean masks elementwise. (Also: must use &, not and — and can't elementwise-combine and tries truthiness of the whole Series.)
