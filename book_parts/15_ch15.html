Robustness · data workflows

Files and Data

▾

What/why. Programs that can't touch files can't touch reality. Data lives in text files (logs, notes), CSV (tables — the lingua franca of data exchange), JSON (nested records, APIs, configs), and behind paths that differ per OS. Python's file story stands on four pillars: open() + with (guaranteed cleanup), the csv/json modules (never hand-parse structured formats), pathlib (paths as objects, not strings), and streaming (process gigabytes in constant memory). Master this chapter and Chapters 25 + all five projects are pure composition.

15.1 open(): modes, encoding, newlines — the complete contract

What. open(path, mode="r", encoding=None, newline=None) returns a file object (a buffered stream): text modes yield str (decoded), binary modes yield bytes (raw). The mode string combines direction (r/w/a/x) + optional + (update), b (binary), t (text, default).

ModeMeaningMissing file?Existing content?
"r" (default)Read textFileNotFoundErrorUntouched
"w"Write (create/truncate)CreatedERASED immediately on open
"a"Append (writes go to end)CreatedKept; cursor at end
"x"Exclusive createCreatedFileExistsError (safe "don't clobber me")
"r+"/"w+"/"a+"Read+write combosVariesSeek/tell juggling — rare, fiddly
"rb"/"wb"/…Binary (no decode, no newline translation)As aboveAs above — bytes in/out

Encoding (non-negotiable). Text mode decodes bytes→str on read and encodes str→bytes on write using encoding=… — which defaults to platform-dependent (locale.getpreferredencoding()): UTF-8 on most macOS/Linux, cp1252 on many Windows setups. Omitting it means "works on my machine, mojibake on yours". Always pass encoding="utf-8"` explicitly (or the file's true encoding — §6.8's debugging guide). New day, new rule: open() without encoding= is a bug report waiting to happen (linters can flag it).

Newlines. Text mode with default newline=None enables universal newlines: \r\n (Windows) and \r (old Mac) are translated to \n on read, and \n is translated back to the OS convention on write. The csv module needs this disabled (newline="" — §15.3) because it handles embedded newlines in quoted fields itself.

the with-guarantee + read shapes 
# ✅ ALWAYS: with (close+flush guaranteed, even on exceptions/returns) + encoding
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("hello\n")        # returns chars written (6)
    f.write("world\n")
    # f is FLUSHED + CLOSED here — even if an exception fired mid-block!

with open("notes.txt", encoding="utf-8") as f:
    text = f.read()           # WHOLE file → one str (fine for KBs, death for GBs!)
print(repr(text))             # 'hello\nworld\n' — !r shows the invisible \n

with open("notes.txt", encoding="utf-8") as f:
    lines = f.readlines()     # ALL lines → list (keeps \n! same memory warning)
print(lines)
print("closed?", f.closed)    # True — `with` closed it (outside the block, f persists but shut)
'hello\nworld\n' ['hello\n', 'world\n'] closed? True

Step-by-step (with). open(…) creates the file object; __enter__ returns it as f; the block runs; then __exit__ runs unconditionally — flushing buffers to the OS and releasing the handle — whether the block finished, returned, or raised (Chapter 21's context-manager protocol; files are its flagship use). Without with, an exception mid-write leaks the handle and loses buffered data — truncated/corrupt files with no error at the loss site.

🚫 The "w"-clobber catastropheopen(path, "w") truncates existing content the instant it opens — before you write a byte. A script that opens its input with "w" by typo, or crashes between open and write, destroys data irrecoverably. Defenses: (1) "x" for outputs that must not exist; (2) atomic write (temp file + os.replace — §15.6) for anything precious; (3) backups/version control for irreplaceable inputs; (4) never use the same path for input and output simultaneously.

15.2 Streaming: files are lazy iterables (process GBs in MBs)

What. A file object is an iterator (Chapter 19's protocol): for line in f: reads and yields one line at a time, buffering ahead invisibly — memory stays flat (~KBs) no matter the file size. This is the big-file technique, composing with generator pipelines (§15.6, Ch. 19).

streaming patterns: count, filter, head, reservoir 
# Setup: a 3-line demo (imagine 30M lines — code is IDENTICAL)
with open("demo.log", "w", encoding="utf-8") as f:
    f.write("INFO start\nERROR boom\nINFO end\n")

with open("demo.log", encoding="utf-8") as f:   # ✅ O(1) memory at ANY size
    for line in f:                              # one line at a time (keeps \n!)
        print("line:", line.strip())            # .strip() removes \n for display

def head(path, n=5):                            # first n lines, never loads all
    out = []
    with open(path, encoding="utf-8") as f:
        for i, line in enumerate(f):
            if i >= n:
                break
            out.append(line.rstrip("\n"))
    return out
print(head("demo.log", 2))

def count_matching(path, word):                 # grep-like counter, streaming
    n = 0
    with open(path, encoding="utf-8") as f:
        for line in f:
            if word in line:
                n += 1
    return n
print("ERROR lines:", count_matching("demo.log", "ERROR"))
line: INFO start line: ERROR boom line: INFO end ['INFO start', 'ERROR boom'] ERROR lines: 1

Memory law. read()/readlines()/list(f) materialize everything (O(file) RAM — fine under ~100MB, fatal at 10GB). Line-iteration and readline()/read(CHUNK) stream (O(1)). Rule: default to streaming; materialize only when random access genuinely needs it (and then check the size first: Path.stat().st_size). Chapter 19's generators turn these loops into composable read → clean → filter → aggregate pipelines.

15.3 CSV: tables done right (never hand-parse)

What. CSV (comma-separated values) is the universal table exchange format — with deceptively tricky rules (RFC 4180): fields containing commas/newlines/quotes get quoted ("pen, fancy"), quotes double ("say ""hi"""), line endings vary. The csv module implements all of it. Hand-parsing with split(",") corrupts real-world CSV — the demo below proves it in 3 lines.

split vs csv: the corruption demo 
line = 'pen, fancy,3,2.5'          # innocent line — split works...
print(line.split(","))              # ['pen', ' fancy', '3', '2.5'] ✓ (but note spaces!)
real = '"pen, fancy",3,2.5'         # REAL line — comma INSIDE quotes
print(real.split(","))              # ['"pen', ' fancy"', '3', '2.5'] — CORRUPT! (4 fields, quotes kept)
import csv
print(next(csv.reader([real])))     # ['pen, fancy', '3', '2.5'] — CORRECT (3 fields, quotes handled)
['pen', ' fancy', '3', '2.5'] ['"pen', ' fancy"', '3', '2.5'] ['pen, fancy', '3', '2.5']
DictReader/DictWriter: the professional CSV shape 
import csv
# WRITE: newline="" is REQUIRED (docs-mandated — else \r\r\n blank rows on Windows!)
with open("sales.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=["item", "qty", "price"])
    w.writeheader()                                            # item,qty,price
    w.writerow({"item": "pen, fancy", "qty": 3, "price": 2.5})  # quoted AUTOMATICALLY
    w.writerow({"item": "book", "qty": 1, "price": 12.0})

with open("sales.csv", newline="", encoding="utf-8") as f:
    reader = csv.DictReader(f)      # first row → fieldnames; each row → dict of STRINGS
    print("fields:", reader.fieldnames)
    for row in reader:              # STREAMING (row by row — big files safe!)
        total = float(row["price"]) * int(row["qty"])  # CSV values ALWAYS str — CONVERT!
        print(row, "→", total)
fields: ['item', 'qty', 'price'] {'item': 'pen, fancy', 'qty': '3', 'price': '2.5'} → 7.5 {'item': 'book', 'qty': '1', 'price': '12.0'} → 12.0

Step-by-step (read path). DictReader consumes the header row as fieldnames; each subsequent physical record (possibly spanning multiple lines if quoted newlines!) becomes an ordered dict mapping fieldname → raw string. All values are strings — int/float conversion is your job, with error handling (Chapter 14's collect-and-continue — never let one bad cell kill a million-row load). Malformed rows (too many/few fields): restkey/restval params or strict validation — choose loudly.

Dialects + TSV + gotchas. csv.reader(f, delimiter="\t") reads TSV; delimiter=";" reads continental CSV; quoting=csv.QUOTE_MINIMAL (default) quotes only when needed. Sniffer (csv.Sniffer().sniff(sample)) guesses dialects — convenient, occasionally wrong (verify fieldnames!). Excel writes BOM (\ufeff) — read with encoding="utf-8-sig" (strips it) or your first column name gains an invisible character (the classic "KeyError on a key that's RIGHT THERE").

15.4 JSON: nested records, APIs, configs

What. JSON (JavaScript Object Notation) encodes nested data: objects ↔ dicts, arrays ↔ lists, strings/numbers/booleans/null ↔ str/int/float/bool/None. The json module converts both directions: dumps (dict→str), loads (str→dict), dump/load (file variants). Boundaries: dump on write, load on read — with indent=2 for humans, compact for machines.

json round-trip + pretty + strictness 
import json
user = {"name": "Ali", "tags": ["vip", "pk"], "vip": True, "note": None, "score": 93.5}
text = json.dumps(user, indent=2)    # dict → JSON string (True→true, None→null)
print(text)
back = json.loads(text)              # JSON string → dict
print(back == user)                  # True — lossless round-trip (for JSON-native types!)
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(user, f, indent=2, ensure_ascii=False)  # keep é😀 readable (not \uXXXX)
# What json CAN'T do: sets, tuples-as-tuples, dates, custom objects:
# json.dumps({"s": {1,2}}) → TypeError! Convert first: {"s": sorted(...)} / isoformat dates.
# Parse failures: json.loads("{bad}") → json.JSONDecodeError (a ValueError — catch it!)
{ "name": "Ali", "tags": [ "vip", "pk" ], "vip": true, "note": null, "score": 93.5 } True

JSONL (JSON Lines) — the big-data sibling. One JSON object per line ({"a":1}\n{"a":2}\n): streamable (parse line-by-line — full-file json.load can't stream!), appendable, grep-able. Logs, event streams, and datasets use it. Pattern: for line in f: obj = json.loads(line) + per-line try/except (one corrupt line shouldn't kill the stream — §14.4).

15.5 pathlib: paths as objects (never string-surgery again)

What. pathlib.Path represents filesystem paths as objects with operators and methods: / joins (cross-platform!), .exists()/.mkdir()/.stat()/.suffix/.stem/.parent inspect, .read_text()/.write_text() shortcut small files, .glob() finds patterns. It replaces os.path.join string-juggling and hardcoded separators.

pathlib: the working set 
from pathlib import Path
p = Path("data") / "2026" / "sales.csv"   # / joins — correct sep on EVERY OS
print(p)                                  # data/2026/sales.csv (shown with / even on Win)
print("suffix:", p.suffix, "| stem:", p.stem, "| name:", p.name, "| parent:", p.parent)
print("exists:", p.exists())
print("parts:", p.parts)                  # ('data', '2026', 'sales.csv') — portable anatomy
print("as_json:", p.with_suffix(".json")) # data/2026/sales.json — swap extensions safely
# Small-file shortcuts (encoding STILL explicit!):
# Path("hi.txt").write_text("hello\n", encoding="utf-8")
# print(Path("hi.txt").read_text(encoding="utf-8"))
# Make trees + find files:
# Path("data/2026").mkdir(parents=True, exist_ok=True)  # mkdir -p (no error if exists)
# print(sorted(Path("data").glob("**/*.csv")))          # recursive find
# NEVER: "data" + "/" + name (breaks on Windows) or f"C:\\fixed\\{x}" (unportable)
data/2026/sales.csv suffix: .csv | stem: sales | name: sales.csv | parent: data/2026 exists: False parts: ('data', '2026', 'sales.csv') as_json: data/2026/sales.json

Relative vs absolute + the cwd trap. Relative paths ("data/x.csv") resolve against the current working directory (where you launched Python — not where the script lives!). Scripts run from another folder break. Robust script pattern: anchor to the script's own location: HERE = Path(__file__).resolve().parent; DATA = HERE / "data" / "x.csv" (Chapter 16 explains __file__). Notebooks: %pwd + absolute-or-anchored paths for anything shared.

15.6 Professional I/O patterns: atomic writes, encodings fallback, size guards

atomic write (crash-safe outputs) 
import os, tempfile
from pathlib import Path

def atomic_write_text(path, text, encoding="utf-8"):
    """Write text so readers NEVER see a half-written file (crash-safe)."""
    path = Path(path)
    fd, tmp = tempfile.mkstemp(dir=str(path.parent), prefix=path.name + ".", suffix=".tmp")
    try:
        with os.fdopen(fd, "w", encoding=encoding) as f:  # fd owned from here
            f.write(text)
            f.flush()
            os.fsync(f.fileno())       # force bytes to DISK (not just OS buffers)
        os.replace(tmp, path)          # ATOMIC rename (POSIX + Windows): instant swap
    except BaseException:
        try: os.unlink(tmp)
        except OSError: pass
        raise

atomic_write_text("report.txt", "all good\n")
print(Path("report.txt").read_text(encoding="utf-8"))
all good

Step-by-step (crash windows). Without atomicity, a crash mid-"w" leaves a truncated file (readers see garbage). With atomic write: crashes during temp-write leave the old file intact (+ an orphaned temp, cleaned on retry); os.replace swaps names atomically (readers see old or new, never half). fsync closes the OS-crash window (power loss with data still in page cache). Cost: one extra copy + fsync latency — pay it for checkpoints, configs, and published datasets; skip for throwaway temps.

encoding fallback + size guard (defensive loader front-end) 
from pathlib import Path

def read_text_flexible(path, encodings=("utf-8-sig", "utf-8", "cp1252")):
    """Try encodings in order; report which worked (logged in real code)."""
    data = Path(path).read_bytes()
    for enc in encodings:
        try:
            return data.decode(enc), enc
        except UnicodeDecodeError:
            continue
    raise UnicodeDecodeError("none of tried encodings worked", data, 0, 1, "")

def guarded_size(path, limit_mb=500):
    size_mb = Path(path).stat().st_size / 1e6
    if size_mb > limit_mb:
        raise ValueError(f"{path} is {size_mb:.0f}MB > {limit_mb}MB — stream it, don't load it!")
    return size_mb

Path("flex.txt").write_text("café\n", encoding="utf-8")
print(read_text_flexible("flex.txt"))
print("size MB:", guarded_size("flex.txt"))
('café\n', 'utf-8-sig') size MB: 6e-06
⚠️ Encoding fallback honestyFallback guesses — cp1252 decodes any byte sequence (never raises!), so it can "succeed" into mojibake. Always report which encoding worked (log it!) and prefer knowing the source encoding (ask the producer, check the spec) over guessing. utf-8-sig first also transparently handles Excel's BOM.

15.8 Interview questions

Q1: Why `with open(...)`? What breaks without it?
with guarantees close() (flush + handle release) via __exit__, even on exceptions/returns. Without it: crashed writes lose buffered data (truncated files), handles leak (resource exhaustion in long jobs), and Windows locks files open. It's the context-manager protocol (Ch. 21) — files are its canonical use.
Q2: Why must csv files open with newline=""? Why is csv data all strings?
The csv module handles newlines itself (quoted fields embed them); universal-newline translation would double them (blank rows on Windows). All values are strings because CSV carries no type information — conversion (int/float/date) with error handling is the reader's job, at the boundary.
Q3: How do you safely overwrite an important output file? What crash windows exist?
Atomic write: temp file in same directory → write → flush → fsync → os.replace (atomic rename). Windows closed: mid-write crash (old intact), OS crash pre-fsync (fsync forces disk), partial visibility (rename is instant). Readers see old-or-new, never half. (§15.6 implementation.)
Q4: Your script works in one folder but FileNotFounds in another. Diagnose.
Relative paths resolve against the process cwd, not the script's folder. Fix: anchor to Path(__file__).resolve().parent for script-adjacent data; accept absolute/config paths for the rest; print Path.cwd() when diagnosing. Never assume launch directory.
