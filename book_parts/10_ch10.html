Control flow

Loops

▾

What/why. Loops repeat work: for iterates over a known collection ("for each row…"), while repeats until a condition changes ("while retries remain…"). Python's for is a for-each over iterables (Chapter 19's protocol) — there is no C-style index loop, because enumerate/range cover those cases readably. The senior skill has two halves: choosing the right iteration tool (range/enumerate/zip/dict-views/generators) and recognizing when a vectorized operation or builtin should replace the loop entirely (the Ch. 24 ladder).

10.1 for: the for-each philosophy + range, enumerate, zip

What. for VAR in ITERABLE: binds VAR to each item in turn and runs the block. The loop variable leaks (it survives after the loop, holding the last item — §10.5). Loop over values directly; reach for indices only when mutation-by-position or parallel structure demands it.

iteration toolkit, completely 
for i in range(3):            # range(stop): 0,1,2 — LAZY (O(1) memory!)
    print(i, end=" ")
print()
for i in range(2, 11, 3):     # range(start, stop-EXCLUSIVE, step)
    print(i, end=" ")
print()
for i in range(5, 0, -1):     # countdown (negative step)
    print(i, end=" ")
print()
names = ["Ali", "Zara"]
for i, n in enumerate(names, start=1):  # index + value (BEST general loop)
    print(f"{i}. {n}")
for n, s in zip(names, [88, 95]):       # PARALLEL — STOPS AT SHORTEST!
    print(n, s)
for n, s in zip(names, [88]):           # Zara silently DROPPED (length mismatch!)
    print("short:", n, s)
for k, v in {"a": 1, "b": 2}.items():   # dicts via .items() (never index a dict!)
    print(k, v)
0 1 2 2 5 8 5 4 3 2 1 1. Ali 2. Zara Ali 88 Zara 95 short: Ali 88 a 1 b 2

Step-by-step (range laziness). range(10**9) stores three integers (start/stop/step, ~48 bytes) and computes each value on demand — it never materializes a billion-item list. list(range(10**9)) would attempt exactly that (~8 GB → MemoryError/death). Rule: range is for counting/looping; only list() it when tiny and genuinely needed as data.

zip` strictness (3.10+). Silent truncation hides length-mismatch bugs (dropped students, misaligned columns!). zip(a, b, strict=True) raises ValueError on unequal lengths — use it whenever inputs must align (parallel columns, paired tests). For intentionally-uneven pairing, itertools.zip_longest fills gaps with a fillvalue` (Chapter 20).

⚠️ Loop anti-patterns (unlearn these)for i in range(len(xs)): x = xs[i] → for x in xs: (direct!) or enumerate (need index). i = 0; for x in xs: …; i += 1 → enumerate. while i < len(xs): … i += 1 → for. Manual indexing is slower, longer, and off-by-one-prone — the for-each exists to delete it.

10.2 while: condition-driven repetition + guaranteed progress

What. while COND: tests before every round (including the first — possibly zero rounds) and repeats while True. Correctness demands guaranteed progress: something in the body must move the state toward falsifying the condition, on every possible path (including continue-skipped ones — §10.3).

while patterns: countdown, retry-bounded, sentinel, Newton 
# 1. Countdown (progress: attempts decreases every round)
attempts = 3
while attempts > 0:
    print("try, left:", attempts)
    attempts -= 1
# 2. Bounded retry (progress: tries increases; CAP prevents infinity)
tries, ok = 0, False
while not ok and tries < 5:
    tries += 1
    ok = (tries == 3)      # pretend flaky work succeeds on try 3
print("succeeded after", tries)
# 3. Sentinel processing (progress: items consumed)
items = [3, 1, 0, 9]
while items:
    x = items.pop(0)       # shrinks every round → terminates (O(n²) though — deque!)
    if x == 0:
        print("hit zero, stop"); break
    print("saw", x)
# 4. Converge (progress: guess improves; tolerance + cap BOTH required!)
guess, target, iters = 10.0, 2.0, 0
while abs(guess*guess - target) > 1e-9 and iters < 100:  # float==never! tolerance!
    guess = (guess + target/guess) / 2   # Newton step for sqrt
    iters += 1
print("sqrt(2)≈", guess, "in", iters, "iters")
try, left: 3 try, left: 2 try, left: 1 succeeded after 3 saw 3 saw 1 hit zero, stop sqrt(2)≈ 1.4142135623730954 in 7 iters

Why while True + break is legitimate (with discipline). For "loop until something inside decides" (event loops, input validation, servers), testing at the top is awkward — while True: with clearly-visible breaks reads better. Discipline: every while True needs an obviously reachable break (preferably first-screen visible) — and for anything that could spin forever, a trip-count/iteration cap or timeout.

🛠️ Infinite-loop rescue + preventionHung? Ctrl+C (KeyboardInterrupt) — in notebooks, ⬛ Stop/Interrupt kernel. Then audit: ① does the condition variable change on every path (or does continue skip the update)? ② float equality that never hits (while x != 0.3: — use tolerance!)? ③ break actually reachable? Prevention: prefer bounded for (range(max_tries)) whenever a cap exists — bounded loops can't hang.

10.3 break / continue / pass / else — the full control panel

Figure 10.1 — Loop execution map
test condition / fetch next item
↓ enter round
continue → abandon round, jump to next test/fetch  ·  break → exit loop NOW  ·  pass → no-op placeholder
↓ loop finishes
else runs ONLY if the loop ended WITHOUT break (natural exhaustion)
control statements, each proven 
# continue: skip noise, keep signal
for x in [1, -2, 3, -4, 5]:
    if x < 0:
        continue          # abandon THIS round (negatives skipped)
    print(x, end=" ")
print()
# break + for-else: search WITHOUT flag variables
nums = [5, 7, 9]
for n in nums:
    if n % 2 == 0:
        print("found even:", n)
        break             # exit NOW — else SKIPPED
else:                     # runs: loop exhausted WITHOUT break
    print("no even number")
# while-else: same rule (else skipped on break)
count = 0
while count < 3:
    count += 1
else:
    print("counted to", count)  # counted to 3
# pass: syntactic placeholder (empty block would be IndentationError)
for x in []:
    pass  # TODO: handle empty case later
1 3 5 no even number counted to 3

Step-by-step (for-else). Each round: even? No (5, 7, 9 all odd) → no break → fetch next. Iterator exhausts → loop ends naturally → else runs. Had any round hit break, control would jump past the else. Mnemonic: else = "no-break" (think nobreak). Uses: search-miss handling, prime testing (no divisor found), validation (no violation found) — all without a found = False flag.

⚠️ break/continue scope: ONE level onlyIn nested loops, break exits only the innermost loop. To exit multiple levels: extract a function and return (best), set a flag + break twice (meh), or raise a private exception (rare). If you need labeled-break, you need a function.

10.4 Nested loops: pairs, grids, and the O(n²) price tag

nested loops: pairs, table, early exit via function 
# All pairs (i, j) with i != j — O(n²) rounds
vals = [1, 2, 3]
pairs = []
for a in vals:            # outer: n rounds
    for b in vals:        # inner: n rounds PER outer → n² total
        if a != b:
            pairs.append((a, b))
print(pairs)  # 6 pairs from n=3
# Multiplication table (nested + str.join formatting):
for r in range(1, 4):
    print(" ".join(f"{r*c:2d}" for c in range(1, 4)))
# Early multi-level exit: FUNCTION + return (the clean pattern)
def find_first_pair_summing_to(xs, target):
    for i, a in enumerate(xs):
        for j in range(i + 1, len(xs)):
            if a + xs[j] == target:
                return (i, j)   # exits BOTH loops instantly
    return None
print(find_first_pair_summing_to([2, 7, 11, 15], 9))  # (0, 1)
[(1, 2), (1, 3), (2, 1), (2, 3), (3, 1), (3, 2)] 1 2 3 2 4 6 3 6 9 (0, 1)

Cost intuition. n=100 → 10,000 inner rounds; n=10,000 → 100,000,000 (minutes). Nested loops over the same large data are the #1 accidental-quadratic (Chapter 24) — always ask: "can a set/dict (Ch. 8) replace the inner loop?" (§10.6's two-sum is the canonical rescue: O(n²) → O(n)).

10.5 Loop variables leak + the iteration protocol (preview)

leak demo + what for really does 
for i in range(3):
    pass
print("leaked i =", i)   # 2 — for-targets bind in the ENCLOSING scope (no block scope!)
# Comprehension variables do NOT leak (3+): [j for j in range(3)] → j undefined after
# What `for x in xs:` ACTUALLY does (Chapter 19's protocol, previewed):
xs = [10, 20]
it = iter(xs)            # 1. ask for an iterator (cursor)
while True:              # 2. fetch until exhausted
    try:
        x = next(it)     # 3. next item (raises StopIteration at end)
    except StopIteration:
        break            # 4. for-loops catch this SILENTLY and exit
    print("item:", x)
leaked i = 2 item: 10 item: 20

Why this matters now. The leak explains "mystery variable" bugs (a stale i reused later — use fresh names or functions to contain loops). The protocol explains everything iterable: strings, files, generators, dicts, ranges, zips — all work in for because all answer iter()/next(). Chapter 19 turns this preview into full mastery (including writing your own iterables).

10.6 When NOT to loop: the replacement ladder

What. Explicit loops are the clearest tool for complex per-item logic — and the slowest for simple bulk transforms. Climb this ladder deliberately:

RungFormWhen
① Explicit loopfor x in xs: …Complex logic, side effects, early exit, per-item errors
② Comprehension[f(x) for x in xs if p(x)]Transform + filter → new collection (Ch. 13)
③ Builtinsum / min / max / any / all / joinReductions — C-speed, zero bookkeeping
④ Stdlib algorithmCounter / groupby / heapq / bisectCounting, grouping, top-N, searching sorted data
⑤ Vectorized (Part 2)NumPy/Pandas opsNumeric bulk work at scale (10–100×, Ch. 24)
climbing the ladder on one task (sum of even squares) 
xs = [1, 2, 3, 4, 5]
total = 0                       # ① loop: clearest, slowest
for x in xs:
    if x % 2 == 0:
        total += x * x
print(total)                    # 20
print(sum(x*x for x in xs if x % 2 == 0))  # ②+③: generator + builtin — best pure-Python
# ⑤ vectorized (Part 2): import numpy as np; a = np.array(xs); print(((a[a%2==0])**2).sum())
20 20
✅ Rule of thumbUnder ~10k items, write whatever is clearest (usually ①/②). Over ~100k in hot paths, climb to ③/④/⑤ — after profiling (Chapter 24). Premature vectorization of cold code wastes readability for zero user-visible gain.

10.7 Interview questions

Q1: What does for-else / while-else do? Give a use case that avoids a flag.
else runs iff the loop exhausted without break (mnemonic: "no-break"). Use: search patterns — break on found, else = not-found handling. Example: prime test (break on divisor, else prime), validation (break on violation, else valid).
Q2: range vs list(range) — memory, and the rule?
range stores start/stop/step (~48B) and computes on demand — O(1) memory for any size. list(range(n)) materializes n objects — O(n) memory (billions = death). Rule: loop over range directly; list() only tiny ranges genuinely needed as data.
Q3: How do you exit nested loops cleanly? Why not flag-chains?
Extract a function and return (exits all levels instantly, names the search, testable). Flag + double-break works but litters logic and breaks down at 3 levels. (Python has no labeled break by design — functions are the answer.)
Q4: Solve two-sum in O(n) and explain why nested loops lose.
Single pass with a seen-dict: for each x, check if target - x was seen (O(1) hash); else store x. O(n) time, O(n) space. Nested loops re-scan the tail per element — O(n²) time (10k items: 100M ops vs 10k). General lesson: inner-loop scans → hash lookups.
