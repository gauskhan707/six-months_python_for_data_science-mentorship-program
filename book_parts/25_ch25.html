25.4 Pure-Python DS patterns (profiling · cleaning · splits · seeding)

profile + clean + split + seed (stdlib only!) 
import csv, json, random
from collections import Counter

random.seed(42)                       # REPRODUCIBILITY: seed ONCE at program start (log it!)
print("seed: 42 (log seeds with results — unseeded runs are unrepeatable!)")

rows = [
    {"id": "1", "age": "30", "city": "Pune"},
    {"id": "2", "age": "", "city": "  pune "},     # missing age, messy city
    {"id": "3", "age": "abc", "city": "Mumbai"},   # bad age
    {"id": "1", "age": "30", "city": "Pune"},      # DUPLICATE
]
# CLEAN: pure per-row (None = reject-with-reason; §14.5 quarantine idea):
def clean(row):
    age = row["age"].strip()
    if not age:
        return None, "missing age"
    try:
        age_i = int(age)
    except ValueError:
        return None, f"bad age {age!r}"
    if not 0 <= age_i <= 120:
        return None, f"age {age_i} out of range"
    return {"id": row["id"], "age": age_i, "city": row["city"].strip().title()}, None

cleaned, rejects = [], []
for i, r in enumerate(rows):
    good, why = clean(r)
    (cleaned if good else rejects).append(good or {"row": i, "why": why})
seen, deduped = set(), []             # DEDUPE by key (set-membership — §24.2!)
for r in cleaned:
    key = (r["id"], r["age"], r["city"])
    if key not in seen:
        seen.add(key)
        deduped.append(r)
# PROFILE: shape + missing + distributions (Counter — §8.3!):
print("clean:", len(deduped), "| rejected:", len(rejects), "| reasons:", Counter(x["why"] for x in rejects))
print("cities:", Counter(r["city"] for r in deduped))
# SPLIT: seeded shuffle → train/test (deterministic!):
random.shuffle(deduped)
cut = int(0.7 * len(deduped)) or 1
train, test = deduped[:cut], deduped[cut:]
print("train/test:", len(train), len(test))
seed: 42 (log seeds with results — unseeded runs are unrepeatable!) clean: 1 | rejected: 2 | reasons: Counter({'missing age': 1, "bad age 'abc'": 1}) cities: Counter({'Pune': 1}) train/test: 1 0

Pattern notes. Seeding: one random.seed(N) (logged!) makes shuffles/splits repeatable — papers/pipelines record seeds as first-class config (NumPy/sklearn: random_state=42 — same idea, later parts). Cleaning: pure per-row + reject-with-reason (never silent drops — counts + reasons logged!). Dedupe: key-tuples + set (O(n), §24.2). Splits: shuffle-then-cut at minimum (stratified/grouped splits in ML parts). Tiny here — the shapes scale to millions (stream §19.5 + validate §14.5 + log §23.3).

25.6 Interview questions

Q1: Why is Python dominant in data science — structurally?
Five structural causes (§25.1): readable glue shared by analysts+engineers (notebook-to-production path), C-speed libraries (Python UX at kernel speed), notebook iteration loop, ecosystem gravity (datasets/APIs/models ship Python-first), general-purpose coverage (scraping→serving in one language). Plus honest limits (loop speed→vectorize, GIL→processes, typing discipline) — seniors name trade-offs, not just wins.
Q2: Map the DS workflow to Python skills — where does "basic Python" end and DS begin?
It doesn't — ~half of DS time IS fundamentals (ingestion/cleaning/validation/plumbing per §25.2–25.3). Walk the workflow: ask(config)→get(files/APIs)→clean(pure+exceptions)→explore(collections/stats)→model(classes/seeds)→communicate(strings/files)→deploy(venvs/logging) — each stage's Python core from this book, each later Part adding its specialized layer.
Q3: Seeding, splits, and reject-with-reason — why do these three matter?
Seeding: repeatability (logged seed → identical shuffles/splits; unseeded = unrepeatable science). Splits: honest evaluation (test unseen; shuffle-then-cut minimum; stratified later). Reject-with-reason: data integrity (counts+reasons logged, quarantine inspectable — silent drops corrupt silently). Demo §25.4's pattern from memory.
