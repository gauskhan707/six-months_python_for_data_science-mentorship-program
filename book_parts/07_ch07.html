Collections

Lists

▾

What/why. A list is an ordered, mutable, heterogeneous sequence — Python's default "bunch of things in order" container. Internally a dynamic array of references: indexing is O(1), appending is amortized O(1) (occasional resize copies), inserting/removing at the front is O(n) (everything shifts). Lists exist because most data is sequential and evolving — rows arrive, scores update, queues reorder — and you need one container that grows, shrinks, sorts, and slices freely. Core law: a list holds references to objects, not the objects themselves (§3.1's balloons, organized in numbered slots).

7.1 Creation: literals, multiplication, conversion, comprehensions

every way to build a list 
scores = [88, 92, 75]              # literal — the 95% case
empty = []                          # empty literal (NOT list() in hot code — slower)
mixed = ["Ali", 30, True, None]     # heterogeneous — legal (uniform preferred)
zeros = [0] * 5                     # [0,0,0,0,0] — SAFE: ints immutable
chars = list("abc")                 # from ANY iterable → ['a','b','c']
rng = list(range(3))                # [0,1,2]
squares = [i*i for i in range(5)]   # comprehension → [0,1,4,9,16] (Ch. 13)
print(scores, empty, mixed, zeros, chars, rng, squares)
[88, 92, 75] [] ['Ali', 30, True, None] [0, 0, 0, 0, 0] ['a', 'b', 'c'] [0, 1, 2] [0, 1, 4, 9, 16]

Why [0]*5 is safe but [[]]*5 is a trap. Multiplication repeats references, not objects: [0]*5 holds the same int 0 five times — harmless, because ints are immutable (rebinding one slot can't affect others). [[]]*5 holds the same list object five times — mutating through one slot mutates all five (§3.3's bug family). Rule: * only with immutables; comprehensions for independent mutables ([[] for _ in range(5)]).

the multiplication trap, proven + fixed 
bad = [[0]] * 3
bad[0].append(99)
print(bad)              # [[0, 99], [0, 99], [0, 99]] — ONE list, 3 aliases!
print(bad[0] is bad[1]) # True — proof
good = [[0] for _ in range(3)]  # fresh object PER slot
good[0].append(99)
print(good)             # [[0, 99], [0], [0]] — independent ✓
print(good[0] is good[1])  # False
[[0, 99], [0, 99], [0, 99]] True [[0, 99], [0], [0]] False

7.2 Indexing, slicing, and unpacking (sequences share the rules)

What. Lists use identical indexing/slicing semantics to strings (Chapter 6): zero-based + negative, stop-exclusive slices that clip instead of raising. New power: slices are assignable (mutability!) — lst[1:3] = [...] splices, and lst[i] = x repoints a single slot.

list indexing + slice assignment (strings can't do this!) 
nums = [10, 20, 30, 40, 50]
print(nums[0], nums[-1], nums[1:4], nums[::-1])  # 10 50 [20,30,40] reversed copy
nums[0] = 99          # repoint slot 0 (rebinding, NOT mutation of int 10)
print(nums)           # [99, 20, 30, 40, 50]
nums[1:3] = [7]       # SPLICE: replace 2 slots with 1 (list SHRINKS)
print(nums)           # [99, 7, 40, 50]
nums[2:2] = [8, 9]    # insert WITHOUT removing (empty slice = pure insertion)
print(nums)           # [99, 7, 8, 9, 40, 50]
del nums[0]           # remove slot 0 (shifts left) → [7, 8, 9, 40, 50]
del nums[::2]         # delete every 2nd → [8, 40]
print(nums)
a, b = [1, 2]         # unpack (length must match) — tuples/lists both
first, *rest = [1, 2, 3, 4]
print(a, b, first, rest)  # 1 2 1 [2, 3, 4]
10 50 [20, 30, 40] [50, 40, 30, 20, 10] [99, 20, 30, 40, 50] [99, 7, 40, 50] [99, 7, 8, 9, 40, 50] [8, 40] 1 2 1 [2, 3, 4]

Step-by-step (splice nums[1:3] = [7]). The slice selects slots 1–2 ([20, 30]); assignment removes those slots and inserts the right side's items at that position — lengths need not match, so the list grows/shrinks. nums[2:2] = [8,9] selects an empty span (gap 2), so nothing is removed — pure insertion. del nums[::2] removes slots 0,2,4,… in one pass. These are the primitives behind every "edit a sequence in place" algorithm.

7.4 Sorting like a professional: key=, stability, sorted()

What. list.sort(key=None, reverse=False) sorts in place with Timsort (O(n log n), stable: equal elements keep their original relative order). key= accepts a function applied once per element; sorting compares the keys (Schwartzian transform — no repeated computation). sorted(iterable, …) returns a new list, leaving the input untouched.

key functions + stability + multi-pass sorting 
users = [("Ali", 30), ("Zara", 25), ("Omar", 35), ("Hina", 25)]
by_age = sorted(users, key=lambda u: u[1])   # new list, original kept
print(by_age)   # Zara25, Hina25, Ali30, Omar35 — note Zara BEFORE Hina (STABLE!)
users.sort(key=lambda u: u[1], reverse=True)  # in place, descending
print(users)
# Multi-criteria: sort by SECONDARY key first, then PRIMARY (stability composes!):
rows = [("b", 2), ("a", 2), ("a", 1)]
rows.sort(key=lambda r: r[0])  # secondary: name → [('a',2),('a',1),('b',2)]
rows.sort(key=lambda r: r[1])  # primary: num → [('a',1),('a',2),('b',2)] names still ordered!
print(rows)
# Or single-pass with tuple keys (no lambda needed):
rows2 = [("b", 2), ("a", 2), ("a", 1)]
print(sorted(rows2, key=lambda r: (r[1], r[0])))  # same result, one sort
# Case-insensitive + numeric-string sorting:
print(sorted(["banana", "Apple", "cherry"], key=str.lower))  # ['Apple','banana','cherry']
print(sorted(["10", "9", "100"], key=int))  # ['9','10','100'] — NOT lexicographic!
[('Zara', 25), ('Hina', 25), ('Ali', 30), ('Omar', 35)] [('Omar', 35), ('Ali', 30), ('Zara', 25), ('Hina', 25)] [('a', 1), ('a', 2), ('b', 2)] [('a', 1), ('a', 2), ('b', 2)] ['Apple', 'banana', 'cherry'] ['9', '10', '100']

Why stability is a superpower. Because equal-keyed rows keep prior order, you can sort by multiple criteria with successive sorts (least-significant first) — or equivalently with tuple keys. Tuple keys compare element-wise ((1,'a') < (1,'b') < (2,'a')), giving multi-column ORDER BY in one line. Mixed directions (age ascending, name descending)? Sort twice, or negate numerics (key=lambda r: (r.age, reverse-string…) — strings can't negate, so two-pass wins).

⚠️ Sorting trapsMixed types don't compare ([1, "a"].sort() → TypeError — normalize with key=str or clean data first) · key runs once per element (pure + cheap, or precompute) · reverse=True reverses comparisons, not the final list (stability preserved within equal keys — subtly different from sorted(...)[::-1]!) · sorting strings is lexicographic/Unicode-codepoint order ("Z" < "a" — use key=str.lower/casefold for human order).

7.5 Copying: assignment vs shallow vs deep (the independence ladder)

What — three levels of independence: (1) b = a — no copy (alias: one object, two names). (2) Shallow copy — new outer list, same inner objects (a.copy(), a[:], list(a)). Sufficient for flat lists of immutables. (3) Deep copy — fully independent clone, recursively (copy.deepcopy(a)). Required for nested structures you will mutate.

Figure 7.1 — Copy depth, visually (● shared, ○ independent)
b = a (alias)a ──→ ● [●, ●]
b ──┘

b = a.copy()a ──→ ● [●, ●]
b ──→ ○ [●, ●]
2 outers, SAME inners

b ──→ ○ [○, ○]

shallow fails on nesting; deep doesn't 
import copy
a = [[1, 2], [3, 4]]
shallow = a.copy()        # new outer; inners SHARED (is-proof below)
deep = copy.deepcopy(a)   # nothing shared
print(shallow[0] is a[0], deep[0] is a[0])  # True False
shallow[0].append(99)     # inner shared → a DAMAGED through the "copy"!
print("a:", a)            # [[1, 2, 99], [3, 4]]
shallow.append([5])       # outer independent → a's LENGTH untouched ✓
print("a:", a, "| shallow:", shallow)
deep[1].append(100)       # deep fully independent → a untouched ✓
print("a:", a, "| deep:", deep)
True False a: [[1, 2, 99], [3, 4]] a: [[1, 2, 99], [3, 4]] | shallow: [[1, 2, 99], [3, 4], [5]] a: [[1, 2, 99], [3, 4]] | deep: [[1, 2], [3, 4, 100]]

Step-by-step. a.copy() allocates a new outer list whose slots reference the same two inner lists (is-True). Appending to shallow[0] mutates the shared inner — visible via a. But shallow.append([5]) mutates only the new outer — a's length is safe. deepcopy recursively clones inners too (is-False everywhere) — full independence at O(size) time and memory.

Decision rule. Flat list of immutables (scores, names)? Shallow (.copy()). Nested or mutable elements you'll mutate? deepcopy. Passing to a function that only reads? No copy at all (references are cheap — §3.1). deepcopy caveats: slower, and chokes on exotic objects (open files, locks, generators) — plus it preserves shared structure and cycles via an internal memo (two aliases to one inner stay aliased in the copy — usually what you want).

7.6 Traversal: values, indices, parallel — and never mutate while iterating

the four traversal idioms 
scores = [88, 92, 75]
for s in scores:                    # 1. values only (simplest, preferred)
    print(s, end=" ")
print()
for i, s in enumerate(scores):      # 2. index + value (BEST general loop)
    print(f"[{i}]={s}", end=" ")
print()
for i in range(len(scores)):        # 3. indices only — ANTI-pattern (use enumerate!)
    scores[i] += 1                  # (only legit need: in-place rewrite by index)
print(scores)
names = ["Ali", "Zara", "Omar"]
for n, s in zip(names, scores):     # 4. PARALLEL walk (stops at SHORTEST!)
    print(f"{n}: {s}")
88 92 75 [0]=88 [1]=92 [2]=75 [89, 93, 76] Ali: 89 Zara: 93 Omar: 76
🚫 Never mutate a list while iterating it forwardRemoving/inserting inside for x in lst: shifts indices under the cursor — elements get skipped silently (no error!). Three fixes: (a) build new: lst = [x for x in lst if keep(x)] (best); (b) iterate a snapshot: for x in lst[:]: + mutate original; (c) iterate reversed indices: for i in range(len(lst)-1, -1, -1): (deletions behind the cursor are safe).
the skip bug, demonstrated + fixed 
nums = [1, 2, 3, 4]
for x in nums:        # ❌ BUG: skips elements!
    if x % 2 == 0:
        nums.remove(x)
print(nums)           # [1, 3] — looks right?! Try [2, 4, 6, 8]:
nums2 = [2, 4, 6, 8]
for x in nums2:
    if x % 2 == 0:
        nums2.remove(x)
print(nums2)          # [4, 8] — WRONG! 4 and 8 survived (skipped after shifts)
fixed = [x for x in [2, 4, 6, 8] if x % 2 != 0]  # ✅ build new
print(fixed)          # [] — correct
[1, 3] [4, 8] []

Step-by-step (why [4, 8] survives). Cursor at index 0 (2): remove → list becomes [4,6,8], cursor advances to index 1 (6) — 4 (now at index 0) never visited. Remove 6 → [4,8], cursor to index 2 — past the end. Loop exits with [4,8] intact. The first example accidentally looked right — the most dangerous kind of bug.

7.7 Nested lists: matrices, grids, and records

matrix patterns: build, access, flatten, transpose 
# ✅ Correct 3×3 (independent rows):
grid = [[0]*3 for _ in range(3)]
grid[0][0] = 9
print(grid)   # [[9,0,0],[0,0,0],[0,0,0]]
# Access: grid[row][col]; rows: grid[0]; columns: [row[1] for row in grid]
print("row0:", grid[0], "| col0:", [row[0] for row in grid])
# Flatten (read as nested loops — outer first):
flat = [cell for row in grid for cell in row]
print(flat)
# Transpose without NumPy:
m = [[1, 2, 3], [4, 5, 6]]
print([list(col) for col in zip(*m)])  # [[1,4],[2,5],[3,6]] — zip(*m) unpacks rows as args!
[[9, 0, 0], [0, 0, 0], [0, 0, 0]] row0: [9, 0, 0] | col0: [9, 0, 0] [9, 0, 0, 0, 0, 0, 0, 0, 0] [[1, 4], [2, 5], [3, 6]]

Step-by-step (zip(*m) transpose). *m unpacks the matrix into separate row arguments: zip([1,2,3], [4,5,6]). zip then walks them in parallel: (1,4), (2,5), (3,6) — the columns. One line, no indices — and a preview of unpacking power (Chapter 11).

Sorting with key=, filtering with comprehensions, zip/enumerate traversal, and Counter histograms are daily data operations. Scale note: list-of-rows Python loops are O(n) PVM steps — fine to ~100k rows; millions → NumPy/Pandas vectorization (Ch. 24–25).

7.8 Interview questions

Q1: append vs extend vs + vs +=? Give outputs and aliasing behavior.
append(x): one item (even if a list → nesting). extend(it): each element, in place, None returned. +: new list, originals untouched. += on lists: in-place extend (aliases see it) — unlike lst = lst + … which rebinds. Demo all four with prints + an alias witness.
Q2: sort() vs sorted()? What does key= do? Is Python's sort stable — and why do you care?
sort(): in-place Timsort, returns None. sorted(): new list from any iterable. key=: function applied once per element; sort compares keys. Stable: equal keys keep original order — enables multi-criteria sorting (secondary-first passes or tuple keys).
Q3: Shallow vs deep copy — when does shallow fail? How do you prove sharing?
Shallow copies only the outer container; nested mutables stay shared (is-True) — mutating nested contents through the "copy" damages the original. Prove with is on inners. Use copy.deepcopy for nested structures (O(size), fails on files/locks). Flat immutables: shallow suffices.
Q4: What happens when you remove items while iterating forward? Show + fix.
Index shifting skips elements silently (§7.6's [4,8] demo). Fixes: build a new filtered list (best), iterate a lst[:] snapshot, or walk reversed indices. No error is raised — that's what makes it dangerous.
