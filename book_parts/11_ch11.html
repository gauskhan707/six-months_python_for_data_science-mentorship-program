Abstraction · deepest chapter

Functions

▾

What/why. A function is a named, reusable, testable unit of logic: inputs (parameters) go in, work happens in an isolated scope, an output (return value) comes out. Functions exist to kill duplication (DRY — Don't Repeat Yourself), name ideas (a well-named call reads as English), isolate complexity (test/debug one thing at a time), and compose programs from trustworthy parts. Data science without functions is copy-pasted notebook chaos where a fixed bug resurrects in cell 34; with functions it becomes a reusable analysis library (Chapter 25). This is the deepest chapter because functions are the hinge of everything after it: scope (12), recursion/closures/decorators (here + 21), classes as function-bundles (18), testing (23), and every project.

Figure 11.1 — Anatomy of a definition and a call
def mean(xs): … ← DEFINITION: creates a function object, binds the name. Body runs ZERO times.
↓ call: mean([10, 20])
arguments bound to parameters → fresh LOCAL frame pushed on the call stack
↓ body executes (names resolve LEGB — Ch. 12)
return value → frame destroyed → value lands at the call site, execution resumes

11.1 Define, call, return — and the None contract

What. def NAME(params): + indented body + return EXPR. Calling (NAME(args)) runs the body with parameters bound to argument objects (references — §3.1, no copying). return exits immediately with a value; falling off the end (or bare return) returns None.

define + call + return, with the object lesson 
def mean(xs):
    """Return the arithmetic mean of a non-empty list."""
    return sum(xs) / len(xs)

print(mean([10, 20, 30]))  # 20.0 — the VALUE lands here
print(mean.__name__, callable(mean))  # mean True — no parens = the OBJECT itself (address varies!)
print(mean([10, 20, 30]) * 2)  # 40.0 — calls are EXPRESSIONS (nestable!)
result = print("hi")       # print DISPLAYS 'hi' but RETURNS None
print(result)              # None — display ≠ return ( §2.2's law, generalized)
def silent(xs):
    total = sum(xs)        # computes... and drops it (no return!)
print(silent([1, 2]))      # None — falling off the end returns None
20.0 mean True 40.0 hi None None

Step-by-step (mean([10, 20, 30])). ① The argument expression [10, 20, 30] evaluates to a list object. ② A new frame is pushed; parameter xs binds to that object (one reference — the list is not copied). ③ Body: sum(xs) → 60, len(xs) → 3, 60/3 → 20.0. ④ return 20.0: frame destroyed, 20.0 substituted at the call site. ⑤ Outer print displays it. Total: definition ran 0 times until called; each call gets a fresh, isolated frame (local variables never leak between calls).

The return contract (professional law). Return values; print at the edges. A function that only prints gives the program nothing to compute with, test, or compose — its result evaporates into pixels. Structure: pure core functions return data; one thin outer layer (CLI main(), notebook cell) prints/displays. Every project in this book follows this shape — and Chapter 23's testability argument depends on it (you can't assert on printed pixels).

⚠️ Return trapsCode after return is dead (unreachable — linters flag it) · return inside a loop exits the whole function (not just the loop — use it for "found it!" (§10.4), fear it when you meant break) · inconsistent returns (return x on one path, implicit None on another) force every caller to None-check — return one type-shape from all paths or raise (Ch. 14).

11.2 Parameters vs arguments: positional, keyword, defaults

What. Parameters live in the definition (placeholders: def train(model, epochs)). Arguments live in the call (actual objects: train("forest", 50)). Binding is positional-or-keyword by default: pass by order (positional) or by name (keyword, any order). Defaults (epochs=10) make parameters optional — evaluated once at def time (this single fact causes §11.3's famous trap).

argument styles, completely 
def train(model="linear", epochs=10, verbose=True):
    return f"{model}: {epochs} epochs, verbose={verbose}"

print(train())                        # all defaults
print(train("forest"))                # positional (by order)
print(train(epochs=50, model="mlp"))  # keyword (any order, self-documenting)
print(train("mlp", verbose=False))    # mixed: positionals FIRST, then keywords
# print(train(model="a", "b"))        # SyntaxError: positional after keyword!
# print(train("a", "b", "c", "d"))    # TypeError: too many positional args
# print(train(speed=5))               # TypeError: unexpected keyword 'speed'
linear: 10 epochs, verbose=True forest: 10 epochs, verbose=True mlp: 50 epochs, verbose=True mlp: 10 epochs, verbose=False

Rules (exact). In calls: all positionals before all keywords; each parameter bound at most once (f(1, x=2) with def f(x) → "multiple values for argument"). In definitions: non-default parameters before defaulted ones (def f(a=1, b): → SyntaxError). Keywords at call sites are documentation that executes: dropna(inplace=True) vs dropna(True) — the first is self-explaining; the second sends readers hunting.

🐍 The mutable-default trap (top-10 interview question)def f(xs=[]): xs.append(1); return xs — the default list is created once, at def time, and shared across all calls that omit it: f() → [1], then f() → [1, 1]. The function "remembers" — spooky, stateful, bug-breeding. Fix (memorize): def f(xs=None): xs = [] if xs is None else xs — fresh list per call. Generalize: defaults must be immutable (None, 0, "", (), frozenset()).
mutable default: the bug + the fix, side by side 
def buggy(item, bag=[]):      # ❌ ONE list shared by all default-calls
    bag.append(item)
    return bag
print(buggy("a"))  # ['a']
print(buggy("b"))  # ['a', 'b'] — LEAKED across calls!

def fixed(item, bag=None):    # ✅ fresh list per call
    if bag is None:
        bag = []
    bag.append(item)
    return bag
print(fixed("a"))  # ['a']
print(fixed("b"))  # ['b'] — independent ✓
print(buggy.__defaults__)  # (['a', 'b'],) — the shared object, red-handed!
['a'] ['a', 'b'] ['a'] ['b'] (['a', 'b'],)

11.3 *args and **kwargs: flexible signatures + call-site unpacking

What. In definitions: *args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict. Parameters after *args become keyword-only (must be passed by name). In calls, */** do the reverse: unpack a sequence/dict into separate arguments.

flexible signatures, completely 
def report(title, *args, scale=1, **kwargs):
    # title: required (positional-or-keyword)
    # *args: extra positionals → TUPLE (possibly empty)
    # scale: KEYWORD-ONLY (sits after *args — must pass scale=...)
    # **kwargs: extra keywords → DICT
    return {"title": title, "args": args, "scale": scale, "meta": kwargs}

print(report("sales", 10, 20, scale=2, region="PK", q="Q1"))
# Unpacking at CALL time:
vals = [1, 2, 3]
print(max(*vals))                 # max(1, 2, 3) → 3
print(*vals, sep="-")            # 1-2-3 — print each element!
cfg = {"sep": "-", "end": "!\n"}
print("a", "b", **cfg)           # a-b! — dict unpacks to keywords
merged = {**{"a": 1}, **{"b": 2}}  # {a:1, b:2} — dict merge via unpacking
print(merged, [*vals, 4])        # [1,2,3,4] — list building via unpacking
{'title': 'sales', 'args': (10, 20), 'scale': 2, 'meta': {'region': 'PK', 'q': 'Q1'}} 3 1-2-3 a-b! {'a': 1, 'b': 2} [1, 2, 3, 4]

When to use each. *args/**kwargs: wrappers and decorators (def wrapper(*a, **k): …; return fn(*a, **k) — forwards any signature, Chapter 21), extensible APIs (accept-and-forward options to a backend), truly variadic functions (max(), print()). Keyword-only (after */*args): config/boolean flags that must be named (sort(reverse=True)-style clarity enforced). Bare * forces keyword-only with no variadics (def f(a, *, b)). Positional-only (/, 3.8+): library APIs whose parameter names aren't contractual (def f(a, b, /, c) — callers can't write a=).

keyword-only, bare *, positional-only 
def strict(a, b, /, c, *, d):
    # a, b: POSITIONAL-ONLY (before /) — f(a=1,...) → TypeError
    # c: normal (either way)
    # d: KEYWORD-ONLY (after *) — f(..., 4) positionally → TypeError
    return (a, b, c, d)
print(strict(1, 2, 3, d=4))     # ✓
print(strict(1, 2, c=3, d=4))   # ✓
# print(strict(a=1, b=2, c=3, d=4))  # TypeError: positional-only!
def save(path, *, overwrite=False, encoding="utf-8"):  # bare * — flags must be named
    return (path, overwrite, encoding)
print(save("f.csv", overwrite=True))
(1, 2, 3, 4) (1, 2, 3, 4) ('f.csv', True, 'utf-8')

11.4 Scope essentials, docstrings, and type hints

Scope in one paragraph (full story: Chapter 12). Parameters and body-variables are local: born at call, dead at return, invisible outside. Reading a name searches Local → Enclosing → Global → Builtin (LEGB); assigning always binds locally unless declared global/nonlocal. Consequence: a function can't accidentally clobber your variables — and you can't "reach in" to grab its locals. Design through the signature: data enters via parameters, exits via return — nothing else crosses the boundary.

Docstrings (mandatory for non-trivial functions). The triple-quoted string as the body's first statement becomes fn.__doc__ — shown by help(fn), IDEs, and doc generators. Format: one-line summary, then Args/Returns/Raises as needed (Google/NumPy style — pick one per project).

Type hints (cheap, high-value documentation). def pct(part: float, whole: float) -> float: — hints are ignored at runtime (zero cost, zero enforcement) but read by humans, IDEs (autocomplete, inline errors), and mypy (a static checker that finds type bugs before running). Hint all public signatures; hint locals only where unclear.

documented + hinted function (the professional shape) 
def pct(part: float, whole: float) -> float:
    """Return part as a percentage of whole.

    Args:
        part: The portion (must be within [0, whole]).
        whole: The total (must be non-zero).

    Returns:
        The percentage, e.g. pct(3, 4) == 75.0.

    Raises:
        ZeroDivisionError: if whole is 0.
    """
    return 100 * part / whole

print(pct(3, 4))
print(pct.__doc__.splitlines()[0])  # first line — tools show this
help(pct)  # full beauty — try it in the REPL!
from typing import get_type_hints
print(get_type_hints(pct))  # {'part': float, 'whole': float, 'return': float}
75.0 Return part as a percentage of whole. Help on function pct in module __main__: pct(part: float, whole: float) -> float Return part as a percentage of whole. ... {'part': <class 'float'>, 'whole': <class 'float'>, 'return': <class 'float'>}

11.5 lambda: anonymous one-expression functions (and their limits)

What. lambda PARAMS: EXPRESSION creates a function object with no name, whose body is a single expression (no statements, no annotations, auto-returned). Use: throwaway callables passed to key=, map/filter/sorted, callbacks, tiny dispatch.

lambda: right uses + the late-binding trap 
users = [("Ali", 30), ("Zara", 25)]
users.sort(key=lambda u: u[1])   # ✅ throwaway key — lambda's home turf
print(users)
print(sorted(["bb", "a", "ccc"], key=lambda s: (len(s), s)))  # tuple keys!
# ✅ dispatch table of tiny ops:
ops = {"add": lambda a, b: a + b, "mul": lambda a, b: a * b}
print(ops["mul"](3, 4))  # 12
# ❌ ANTI-PATTERNS:
# square = lambda x: x**2   → use `def square(x): return x**2` (PEP 8: name it! no annotations, worse tracebacks)
# THE late-binding trap: lambdas capture VARIABLES, not values!
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])  # [2, 2, 2] — NOT [0,1,2]! all share final i=2
fixed = [lambda i=i: i for i in range(3)]  # default binds CURRENT value
print([f() for f in fixed])  # [0, 1, 2] ✓
[('Zara', 25), ('Ali', 30)] ['a', 'bb', 'ccc'] 12 [2, 2, 2] [0, 1, 2]

Step-by-step (late binding). Each lambda: i stores a reference to the variable i (the loop's single binding — §10.5's leak!), not a snapshot. After the loop, i == 2; calling any lambda reads i now → 2, three times. The i=i default evaluates at definition time (per iteration), freezing each value. Same trap bites def closures in loops (§11.7) — one mechanism, both constructs.

11.6 Recursion: self-similar problems, base cases, and limits

What. Recursion solves a problem by having the function call itself on a smaller subproblem, until reaching a base case solvable directly. Every recursion needs: (1) base case(s) that stop, (2) a recursive step that shrinks toward them, (3) combination of sub-results. Missing any → infinite recursion → RecursionError (CPython caps ~1000 frames — sys.getrecursionlimit()).

Intuition. Russian dolls with instructions: "to open doll N: open doll N−1, then handle your layer" — plus "doll 0: just hand over the prize" (base case). The call stack is the pile of half-opened dolls: each frame waits while deeper frames finish, then resumes. Trace any recursion as down (calls, shrinking) then up (returns, combining).

factorial: trace down, then up 
def factorial(n):
    print("  " * (5-n) + f"call fact({n})")
    if n <= 1:                       # BASE CASE — the stopper (without: RecursionError)
        print("  " * (5-n) + "→ base: return 1")
        return 1
    sub = factorial(n - 1)            # SHRINK toward base
    result = n * sub                  # COMBINE on the way up
    print("  " * (5-n) + f"→ return {n}*{sub}={result}")
    return result

print("answer:", factorial(5))
call fact(5) call fact(4) call fact(3) call fact(2) call fact(1) → base: return 1 → return 2*1=2 → return 3*2=6 → return 4*6=24 → return 5*24=120 answer: 120

Multiple examples — where recursion shines vs flops:

recursion: trees (great) vs naive fibonacci (terrible) 
# GREAT: nested structures (depth unknown, shape self-similar)
def deep_sum(obj):
    if isinstance(obj, (int, float)) and not isinstance(obj, bool):
        return obj                      # base: a number
    if isinstance(obj, (list, tuple, set)):
        return sum(deep_sum(x) for x in obj)  # shrink: each element
    if isinstance(obj, dict):
        return sum(deep_sum(v) for v in obj.values())
    return 0                            # base: anything else contributes 0
print(deep_sum({"a": [1, 2, {"b": 3}], "c": (4,)}))  # 10

# TERRIBLE: naive fibonacci — exponential recomputation!
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)  # fib(30): ~2.7M calls!
import functools
@functools.lru_cache(maxsize=None)   # memoize: each n computed ONCE → O(n)!
def fib_fast(n):
    return n if n < 2 else fib_fast(n-1) + fib_fast(n-2)
print(fib_fast(100))  # instant (naive fib(100): longer than the universe)
10 354224848179261915075

Recursion vs iteration (professional judgment). Use recursion when the data is recursive (trees, nested JSON, filesystems, grammars) — the code mirrors the shape. Use iteration for linear repetition (counting, scanning, accumulating) — no stack risk, less overhead, no limit. Python has no tail-call optimization (deliberately — tracebacks stay complete), so deep linear recursion always risks RecursionError; convert with an explicit stack list when depth is unbounded.

11.7 Closures: functions that remember their birthplace

What. A closure is a function object bundled with references to the enclosing scope's variables it uses — even after the enclosing function has returned. Mechanism: inner def reads outer variables (LEGB's E); Python stores them in fn.__closure__ cells. Writing to them needs nonlocal (else assignment makes a local — Chapter 12).

counter closure, dissected 
def make_counter(step=1):
    count = 0                       # enclosing variable — the closure's memory
    def inc():
        nonlocal count              # WITHOUT this: UnboundLocalError (assigns local!)
        count += step               # write to the CAPTURED cell
        return count
    return inc                      # return the inner function (closure attached!)

c1 = make_counter()                 # own cell: count=0
c2 = make_counter(step=10)          # SEPARATE cell: independent memory!
print(c1(), c1())                   # 1 2
print(c2())                         # 10 — independent ✓
print(c1.__closure__[0].cell_contents)  # 2 — peek at the captured cell!
# Factory pattern: one template, many configured functions:
def make_adder(n):
    return lambda x: x + n           # each remembers its OWN n
add5 = make_adder(5)
print(add5(10))  # 15
1 2 10 2 15

Step-by-step. make_counter() runs: frame created, count = 0 bound, inc defined (capturing the cell for count, not a copy), frame "returns" — but the cell survives, referenced by the closure. Each c1() call: reads/writes the cell via nonlocal. c2 = make_counter(10) runs the factory again → fresh frame → fresh cell → fully independent counter. Closures are stateful functions — objects with one method, no class needed (Chapter 18 shows when to upgrade to classes).

⚠️ Closure trapsForgetting nonlocal on write → UnboundLocalError (read-before-local-assign). Loop-variable capture (§11.5's [2,2,2]) — defaults freeze values. Over-closure: capturing large objects keeps them alive as long as the closure lives (memory leak shape — capture only what you need, or use weakrefs).

11.8 Higher-order functions + decorators from first principles

What. Functions are objects (§3.1): passable as arguments, returnable, storable in lists/dicts. A higher-order function takes or returns functions (map, filter, sorted(key=…), and every decorator). A decorator is a higher-order function that takes a function and returns an enhanced wrapper — with @name as the rebinding syntax: @d def f(…) is exactly f = d(f) executed at definition time.

decorator from zero: no magic, just closures + rebinding 
import functools

def once(fn):
    """Allow fn to run once; later calls get a message."""
    done = False                          # closure memory (per-decorated-function!)
    @functools.wraps(fn)                  # preserve __name__/__doc__ (ALWAYS!)
    def wrapper(*args, **kwargs):         # accept ANY signature
        nonlocal done
        if done:
            return "(already ran)"
        done = True
        return fn(*args, **kwargs)        # call THROUGH + return the result!
    return wrapper

@once                # greet = once(greet) — rebinds the NAME to the WRAPPER
def greet(name):
    """Say hello."""
    return f"hello, {name}"

print(greet("Ali"))   # hello, Ali (wrapper ran fn)
print(greet("Zoe"))   # (already ran) (wrapper short-circuited)
print(greet.__name__, "|", greet.__doc__)  # greet | Say hello. (wraps preserved!)
hello, Ali (already ran) greet | Say hello.

Step-by-step. At def time: greet (original) is passed to once, which builds wrapper (closure over fn + done) and returns it; the name greet is retied to the wrapper (original reachable only via greet.__wrapped__). At call time: your arguments hit wrapper → checks done → first call runs fn(*a, **k) and returns its result; later calls short-circuit. functools.wraps copies metadata so the wrapper impersonates the original (without it: __name__ == "wrapper", doc lost, debuggers confused, stacked decorators degraded).

Three decorator rules (preview of Chapter 21's full treatment). ① Always @functools.wraps(fn). ② Wrapper signature (*args, **kwargs) + return fn(*args, **kwargs) (forgetting return turns every decorated function into a None-machine!). ③ Decorators with arguments (@retry(times=3)) are factories returning decorators — one more nesting level. Builtins you already use that are decorators: @property, @staticmethod, @classmethod (Ch. 18), @lru_cache (§11.6), @contextmanager (Ch. 21).

11.9 Designing good functions (the craft rules)

  • One job. If the name needs "and" (load_and_clean_and_plot), split it. Test: describe it in one sentence without "and".
  • Small. ~5–20 lines; fits on one screen. Long function = hidden sub-functions begging for names.
  • Few parameters. ≤ 3–4; bundle the rest into a dataclass/config/dict. Boolean params are a smell (the function does two things — split or keyword-only it).
  • Pure when possible. Same inputs → same output, no mutation, no I/O. Pure functions are trivially testable, composable, cacheable, parallelizable. Push impurity (I/O, randomness, time) to the edges.
  • Return, don't print (§11.1). Validate at boundaries, assert inside (user input → if/raise; internal invariants → assert; Ch. 14/22).
  • Name as contract: verb + object (parse_date, total_revenue), honest about effects (get_or_create, ensure_dir), no abbreviations the team must decode.

11.10 Interview questions

Q1: Explain *args and **kwargs — both directions — with the wrapper use case.
In definitions: *args gathers extra positionals (tuple), **kwargs extra keywords (dict); params after * are keyword-only. In calls: */** unpack sequences/dicts into arguments. Canonical use: transparent wrappers — def wrapper(*a, **k): log(); return fn(*a, **k) — forwarding any signature (decorators, proxies, API evolution).
Q2: What happens with no return statement? Why is print not a substitute for return?
The function returns None. print emits pixels for humans; return hands a value to the program for computation, testing (assert f(x) == …), and composition (g(f(x))). Print-instead-of-return yields untestable, unchainable code — return from cores, print at edges.
Q3: The mutable-default-argument trap: demo, root cause, fix.
Demo: def f(xs=[]): xs.append(1); return xs → [1] then [1,1]. Cause: defaults evaluate once at def time; the list is shared (fn.__defaults__ proves it). Fix: xs=None + build inside. Generalize: immutable defaults only.
Q4: What is a closure? What is nonlocal for? Give a use.
A function bundled with its enclosing scope's referenced variables (cells surviving the outer return — fn.__closure__). nonlocal declares write-access to an enclosing (non-global) binding — without it, assignment creates a shadowing local (UnboundLocalError on read-first). Uses: counters, factories (make_adder), decorators (wrapper state like done/cache).
Q5: What does @decorator do, exactly? Why functools.wraps?
@d def f ≡ f = d(f) at definition time: decorator receives the function object, returns (usually) a closure wrapper. functools.wraps copies __name__/__doc__/__module__ (+ __wrapped__) so introspection, docs, tracebacks, and stacking keep working.
