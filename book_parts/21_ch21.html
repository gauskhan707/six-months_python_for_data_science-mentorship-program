Power patterns

Decorators and Context Managers

▾

What/why. Two patterns separate scripts from systems. Decorators (@name) wrap functions/classes to add behavior — timing, caching, validation, retries, auth — without editing them (open/closed principle: open for extension, closed for modification). Context managers (with) guarantee setup/teardown pairing — files close, locks release, transactions commit-or-rollback, directories restore — even across exceptions, returns, and breaks. Both rest on one foundation: functions are objects (§3.1/11.8) + closures capture state (§11.7). This chapter takes both from mechanism to mastery: factories, stacking order, class-vs-generator CMs, suppression semantics, and the stdlib's greatest hits.

21.1 Decorators from zero: rebinding + closure + wraps (the whole trick)

What — the complete mechanism in one sentence: @d def f(…): … is exactly def f(…): … followed by f = d(f) — the decorator receives the function object at definition time and whatever it returns becomes the name. The usual return is a closure wrapper adding before/after behavior around a call-through.

timer: the canonical decorator, fully annotated 
import functools, time

def timer(fn):
    @functools.wraps(fn)              # ① preserve __name__/__doc__/__module__ (+__wrapped__) — ALWAYS
    def wrapper(*args, **kwargs):     # ② accept ANY signature (transparent!)
        start = time.perf_counter()
        result = fn(*args, **kwargs)  # ③ call THROUGH (the only fn-specific line!)
        print(f"{fn.__name__} took {time.perf_counter()-start:.4f}s")
        return result                 # ④ MUST return it (else decorated fns → None!)
    return wrapper                    # ⑤ decorator RETURNS the wrapper (becomes the name)

@timer                                # slow = timer(slow) — executed ONCE, at def time
def slow(n):
    """Sum squares."""
    return sum(i*i for i in range(n))

print(slow(200000))                   # wrapper runs: time → call → print → return
print("name:", slow.__name__, "| doc:", slow.__doc__)  # preserved by wraps ✓
print("inner:", slow.__wrapped__.__name__)  # wraps links back (debuggers/tests use this!)
slow took 0.0102s (varies by machine — prints first, inside the call) 666666666700000 name: slow | doc: Sum squares. inner: slow

Step-by-step (two phases). Definition time: slow (original) → timer(slow) builds wrapper (closure over fn) → name slow retied to wrapper. Original survives only as the closure cell + __wrapped__. Call time: your args hit wrapper → clock starts → fn(*a, **k) runs the original → elapsed prints → result returns. Without wraps: __name__ == "wrapper", docstring lost, signature hidden, stacked decorators + help() + test names degrade — always wrap.

⚠️ Decorator traps (all classic)Forgetting return fn(*a, **k) (None-machine!) · fixed wrapper signature (def wrapper(x) breaks other arities — use *a/**k) · forgetting wraps (identity theft) · decorating methods without accounting for self (fine with *a/**k — self just flows through!) · state in the decorator body shared across functions (put per-function state in the closure, §11.8's done).

21.2 Decorator factories: @retry(times=3) (one more nesting level)

What. @retry(times=3) calls retry(times=3) first — which must therefore return a decorator. Three levels: factory(args) → decorator(fn) → wrapper(*a, **k). Read inside-out: the factory configures, the decorator binds, the wrapper runs.

retry factory + validate + count (practical trio) 
import functools, time

def retry(times=3, delay=0.0, allowed=(Exception,)):
    """Factory: build a decorator retrying on `allowed`, `times` tries, `delay` apart."""
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            last = None
            for attempt in range(1, times + 1):
                try:
                    return fn(*args, **kwargs)   # success → return immediately
                except allowed as e:            # failure → record, sleep, retry...
                    last = e
                    print(f"  try {attempt}/{times} failed: {e}")
                    if delay:
                        time.sleep(delay)
            raise last                          # ...exhausted → re-raise LAST (traceback kept!)
        return wrapper
    return decorator

def positive(fn):                               # validator decorator (no factory — direct)
    @functools.wraps(fn)
    def wrapper(x, *args, **kwargs):
        if x <= 0:
            raise ValueError(f"{fn.__name__} needs x > 0, got {x}")
        return fn(x, *args, **kwargs)
    return wrapper

calls = {"n": 0}
@retry(times=3, allowed=(ValueError,))
def flaky():
    calls["n"] += 1
    if calls["n"] < 3:
        raise ValueError(f"boom {calls['n']}")
    return "recovered!"

print(flaky())                                   # recovered! (after 2 logged failures)

@positive
def root(x):
    return x ** 0.5
print(root(16))                                 # 4.0
# root(-1) → ValueError: root needs x > 0, got -1
try 1/3 failed: boom 1 try 2/3 failed: boom 2 recovered! 4.0

Step-by-step (@retry(times=3, …)). ① retry(times=3, allowed=…) executes → returns decorator (closure over config). ② decorator(flaky) executes → returns wrapper (closure over fn + config). ③ Name flaky retied. Calls hit wrapper: loop tries → success returns / failure logs + retries / exhaustion re-raises last (original traceback preserved — never raise DifferentError bare here; chain with from if translating — §14.3).

21.3 Stacking: order is behavior (@a @b def f = a(b(f)))

stacking order, proven with probes 
import functools

def tag(name):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*a, **k):
            print(f"  [{name}: before]")
            out = fn(*a, **k)
            print(f"  [{name}: after]")
            return out
        return wrapper
    return deco

@tag("A")          # applied LAST (outermost): A(B(f)) — A.before runs FIRST
@tag("B")          # applied FIRST (innermost): wraps f directly
def work():
    print("  [work]")
    return 42

print(work())
# Read: def work → B(work) → A(B(work)). Calls: A.before → B.before → work → B.after → A.after.
# Real-world stacking logic: @timer OUTER (measure everything incl. retries),
# @retry MIDDLE, @lru_cache INNER (hits skip retry+timer — usually right!).
[A: before] [B: before] [work] [B: after] [A: after] 42

Why order matters (beyond cosmetics). Each layer transforms what inner layers see: cache-inside-retry means failures aren't cached, successes skip retries (desired); retry-inside-cache means cache hits return instantly, misses retry (also sensible — different!). Auth-outside-timer times only authorized work. Argue each stack from the call-path: outermost runs first/last (setup/teardown span), innermost touches the original directly.

21.4 Class decorators + method decorators + parameters preserved

What. Decorators accept any callable target: decorating a class passes the class object (@dataclass itself! — it rewrites __init__/__repr__/__eq__); decorating methods works identically (the wrapper's *args receives self first — flows through untouched). Signature preservation beyond wraps (for inspect.signature fidelity) needs functools.wraps + __wrapped__ following (automatic) — full ParamSpec typing (3.10+) for library authors.

register pattern (class+function decorator) + method wrap 
import functools
REGISTRY = {}
def register(name):
    """Class/function decorator: record target in REGISTRY, return UNCHANGED."""
    def deco(target):
        REGISTRY[name] = target
        return target          # NOT a wrapper — pure side-effect registration!
    return deco

@register("csv")
class CsvReader:
    pass
@register("double")
def double(x):
    return x * 2
print(sorted(REGISTRY))  # ['csv', 'double'] — plugin discovery, zero config files!

print(double(21))              # 42 — registered targets work NORMALLY (deco returned them unchanged!)
# (Timer-on-method demo: @timer works on methods too — self flows through *args. See §21.1!)
['csv', 'double'] 42

21.5 Context managers: the with-contract (setup → body → guaranteed teardown)

What. with EXPR as VAR: ① evaluates EXPR, ② calls __enter__() (result → VAR), ③ runs the body, ④ calls __exit__(exc_type, exc, tb) no matter how the body ends (normal, exception, return, break, continue!). If the body raised, the exception details arrive as __exit__'s args; returning truthy from __exit__ suppresses it (rare, deliberate — §21.6); falsy/None re-raises after teardown.

class CM: full protocol + exception visibility 
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self                        # `as t` gets THIS
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        print(f"  block took {self.elapsed:.4f}s; exc={exc_type.__name__ if exc_type else None}")
        return False                       # do NOT suppress (None/False → exception propagates!)

with Timer() as t:
    total = sum(range(100000))
print("total:", total, "| measured:", round(t.elapsed, 4) >= 0)

try:
    with Timer():
        raise ValueError("boom")           # teardown STILL runs, THEN boom propagates
except ValueError as e:
    print("propagated:", e)
block took 0.0016s; exc=None total: 4999950000 | measured: True block took 0.0000s; exc=ValueError propagated: boom

Step-by-step (exception path). Body raises ValueError → Python captures (type, value, traceback) → calls __exit__(ValueError, err, tb) → teardown prints (elapsed measured!) → returns False → original exception re-raised to the outer try. The teardown observes the failure (can log/commit-or-rollback on it!) without consuming it. That's the whole power: cleanup code that sees how the body ended.

21.6 @contextmanager: the generator shortcut (+ suppression done right)

generator CMs: temp-flag + cd + suppress-pattern 
import contextlib, os
from pathlib import Path

@contextlib.contextmanager
def temp_flag(store, key, value):
    """Set store[key]=value for the block; ALWAYS restore after (even on error)."""
    sentinel = object()                    # unique "was absent" marker (safer than None!)
    old = store.get(key, sentinel)
    store[key] = value
    try:
        yield store                        # ← body runs HERE (value → `as s`)
    finally:
        if old is sentinel:                # teardown IN finally (the whole point!)
            store.pop(key, None)
        else:
            store[key] = old

cfg = {"debug": False}
with temp_flag(cfg, "debug", True) as s:
    print("inside:", s)
print("outside:", cfg)                     # restored ✓

@contextlib.contextmanager
def cd(path):                              # chdir with guaranteed restore
    prev = os.getcwd()
    os.chdir(path)
    try:
        yield Path(path)
    finally:
        os.chdir(prev)

import tempfile
with tempfile.TemporaryDirectory() as td:  # REAL cd demo in a safe sandbox dir!
    here = Path.cwd()
    with cd(td):
        print("inside tmp:", Path.cwd().resolve() == Path(td).resolve())  # True
    print("restored:", Path.cwd() == here)  # True — guaranteed, even on error!
# Suppression (RARE + explicit): contextlib.suppress(n) swallows ONLY listed errors:
with contextlib.suppress(FileNotFoundError):
    os.unlink("definitely_missing.tmp")    # no crash, no try/except noise
print("suppressed ✓ (prefer this over try/except/pass — intent is VISIBLE)")
inside: {'debug': True} outside: {'debug': False} inside tmp: True restored: True suppressed ✓ (prefer this over try/except/pass — intent is VISIBLE)

Generator-CM mechanics (exact). Code before yield = __enter__; the yielded value = as-target; an exception in the body is thrown into the generator at the yield (so try/finally around it runs teardown, then the exception continues — matching class-CM falsy-return); return value in the generator is ignored (bare return ends early). Rule: exactly one yield, wrapped in try/finally (teardown in finally — a bare post-yield line skips on exception!). Choose class-CMs when: reusable/configurable (init args), suppression logic, or __enter__ may fail independently. stdlib hits: contextlib.suppress (visible swallowing), redirect_stdout (capture prints in tests!), ExitStack (dynamic N managers — §21.7).

21.7 Multiple + dynamic managers (ExitStack) + real-world map

stacked with + ExitStack for dynamic counts 
import contextlib
from pathlib import Path

@contextlib.contextmanager
def temp_flag(store, key, value):   # §21.6's CM, restated (each listing runs standalone!)
    had, old = key in store, store.get(key)
    store[key] = value
    try:
        yield store
    finally:
        if had:
            store[key] = old        # restore prior value
        else:
            store.pop(key, None)    # remove what we added

# Fixed N: comma-stack (or nested with) — exits run REVERSE order (LIFO: c, b, a):
with temp_flag({}, "a", 1) as a, temp_flag({}, "b", 2) as b:
    print("stacked:", a, b)
# Dynamic N (open len(paths) files — can't write N `with` lines!):
paths = ["f1.tmp", "f2.tmp"]
for p in paths:
    Path(p).write_text(p + "\n", encoding="utf-8")
with contextlib.ExitStack() as stack:
    files = [stack.enter_context(open(p, encoding="utf-8")) for p in paths]
    print([f.read().strip() for f in files])  # ALL closed at block end (even mid-error!)
for p in paths:
    Path(p).unlink()
print("all closed ✓")
stacked: {'a': 1} {'b': 2} ['f1.tmp', 'f2.tmp'] all closed ✓

21.8 Interview questions

Q1: What does @deco do — exactly, in which phase? Why functools.wraps? The three wrapper rules?
@d def f ≡ f = d(f) at definition time; decorator returns (usually) a closure wrapper becoming the name; calls hit the wrapper → before/after + call-through. wraps preserves __name__/__doc__/__module__ + __wrapped__ (introspection/docs/stackability). Rules: (*a, **k) signature, return fn(*a, **k), wraps — violate any and decorated functions degrade (None-machine/arities/identity-theft).
Q2: Decorators with arguments — the three levels? Stacking order semantics?
Factory(config) → decorator(fn) → wrapper(*a/**k): @retry(n=3) calls the factory first. Stacking: @a @b def f = a(b(f)) — bottom applies first (innermost, touches original), top runs first/last per call. Order is behavior (cache-inside-retry vs retry-inside-cache differ!) — argue from the call path.
Q3: How does `with` guarantee cleanup? Class vs @contextmanager? Suppression semantics?
__enter__ → body → __exit__(type, val, tb) unconditionally (normal/exception/return/break). Generator-CMs: pre-yield = enter, try/finally around yield = teardown (mandatory pattern!). Truthy __exit__ return suppresses the body exception (rare/deliberate — prefer contextlib.suppress for visibility). DB transactions branch commit/rollback on exc presence.

  2. Show __name__/__doc__ with and without wraps; show __wrapped__ recovery. Break stacking without wraps (two undecorated layers) and describe symptoms.
  3. Write a class CM logging enter/body-outcome/exit for normal + raising bodies; show __exit__ args in both.
Level 2 · Apply
  1. @retry(times, delay, allowed, backoff=2.0) with exponential backoff + jitter; prove exhaustion re-raises the LAST error (traceback intact).
  2. @contextmanager cd(path) + temp_env(var, value) (os.environ save/restore); test exception-path restoration for both.
  3. Stack @timer @retry @lru_cache on a flaky fib: predict behavior per order, verify with probes, defend the right order in comments.
Level 3 · Interview
  1. Implement a mini transaction CM over a dict-store (snapshot on enter; commit on clean exit; rollback on exception; nested-transaction behavior documented). Test all paths.
  2. Write a decorator preserving inspect.signature strictly (investigate __wrapped__ chaining + inspect.signature(follow_wrapped=True)); then break it with *a/**k opacity and discuss ParamSpec as the principled fix.
